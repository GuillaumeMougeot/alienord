# nvgpu-fix: rebuilding NVIDIA's GPU driver for this unit

Rebuilds `nvgpu.ko` (L4T 35.1) with NVIDIA's own clock-arbiter / PM-QoS fix from L4T 35.2.1, for
the exact kernel running on the unit (Lenovo's build). Why:
[journal](../../journal/2026-11-19-can-the-gpu-driver-be-fixed.md). Testing, installing and
recovering: [runbook](../../docs/gpu-driver-fix.md).

Built on the unit itself in `/home/xnx/build/nvgpu-fix/` (outside the repository: sources, build
tree, 250 MB of objects). This folder keeps what is needed to redo it.

## The problem with the headers, and how it was solved

The installed `nvidia-l4t-kernel-headers 35.1.0` were built by NVIDIA (2022) with module signing
on; the running kernel is Lenovo's 2023 build with it off. 156 of nvgpu's 388 imported symbols
have different version checksums, so a module built against the headers as shipped is refused.

1. **Config:** the header tree's `.config` is replaced by `/proc/config.gz`. Kconfig cannot run in
   a headers-only tree (NVIDIA overlay Kconfig files missing), so `gen_autoconf.py` writes
   `include/generated/autoconf.h` and `include/config/auto.conf` directly; it reproduces NVIDIA's
   own two files byte-for-byte from NVIDIA's `.config` (validation).
2. **Checksums (`Module.symvers`):** `image_crcs.py` reads every exported symbol's CRC straight
   out of `/boot/Image` (the `__ksymtab`/`__kcrctab` tables; 13,872 symbols).
   `harvest_crcs.py` collects the CRCs recorded in the 1,095 modules Lenovo built (the 3 NVIDIA
   display modules in `extra/opensrc-disp` are from 2022 and never load: excluded).
   `symvers_from_image.py` merges them: all 5,018 overlapping values agree, 0 disagree.
3. **Proof the types match:** compiling the kernel's own `module.c` and `qos.c` in this tree gives
   `module_layout = 0xc23f4489` and `dev_pm_qos_add_notifier = 0xb64e7201`, exactly the values in
   the running kernel image (the NVIDIA headers say `0x4e1b2ba3` for the latter).

## The patch

`nvgpu-35.1-clk-arb-qos-backport.patch`, generated by `make_patch.py` from NVIDIA's 35.1 → 35.2.1
diff, keeping only the clock/QoS change (11 files, 249 changed lines):

- `Makefile.linux.configs`: `CONFIG_GK20A_PM_QOS := y` (was `n` in 35.1);
- `scale.c/.h`: per-device min/max frequency QoS notifiers for kernel 5.10, and
  `gk20a_scale_clamp_clk_target()`; `gk20a_scale_target` keeps EMC scaling when the arbiter is active;
- `clk_arb_gp10b.c` (and `clk_arb_gv100.c`): clamp the arbiter's target to the QoS min/max and
  record `g->last_freq`. **This is the line that stops the 1109 MHz jump**;
- platform files, `driver_common.c`, `vgpu_linux.c`: the new callbacks wired in.

Left out from 35.2.1: everything else (gr init wait, TPC masks, host1x, bpmp check, nvsched…).

## Checks done

- Unmodified 35.1 build vs Lenovo's module (`compare_ko.sh`): same vermagic, same 388 imports with
  identical CRCs, same 6,600 symbols, identical `.data`, `.bss`, `.rodata`, `.rodata.str1.8` sizes,
  same text strings (except compiler name and `intree`). Code 1.4 % smaller (gcc 9.4 vs Lenovo's
  9.3). So Lenovo did not change NVIDIA's nvgpu.
- Fixed build vs unmodified: +3 functions (`gk20a_scale_clamp_clk_target`, `…qos_min_notify`,
  `…qos_max_notify`), −1 (`gk20a_scale_qos_notify`), +2 imports (`dev_pm_qos_add/remove_notifier`).
- Every import of the fixed module: 387 match `/boot/Image`; the other 3 are nvmap exports,
  identical to Lenovo's module.
- Out-of-tree modules lack `intree=Y`: loading it marks the kernel tainted `O`. Cosmetic.

Result: `nvgpu-fixed.ko`, sha256 `761608e899ce995218b26393d223aa7d14ea5c32cb15efd8d1a669bb3242f3ec`
(debug info stripped, as Lenovo's).

## Redo

```bash
B=/home/xnx/build/nvgpu-fix     # holds dl/, src/, kh/ (copy of the headers package), tools/root (make)
tools/build.sh $B/fix           # nice -n 19, -j2: ~12 min, unit at ~14-15 W while building
strip --strip-debug -o $B/fix/nvgpu-fixed.ko $B/fix/drivers/gpu/nvgpu/nvgpu.ko
python3 -I tools/image_crcs.py /boot/Image $B/kh/kernel-5.10/Module.symvers --ko $B/fix/nvgpu-fixed.ko
```

`gpu-driver-live-test.sh`: the run-time swap test of 11-19. **Do not use**: reloading `nvgpu` at run time crashes the kernel on this unit, with the original driver too.

After the 11-19 14:14 crash (option A, owner's choice): `gpu-driver-reload-original.sh` unloads and
reloads the **original** driver the same way, with crash capture on (`ramoops`, `kernel.panic=10`),
to learn whether a run-time reload alone crashes the kernel. `read-crash-record.sh` copies the saved
record after a crash reset. Both are run from `/home/xnx/gpu-test/` (`/tmp` is wiped at boot).

`trial/`: the one-boot trial (11-19, passed). `perm/`: the permanent setup, fixed driver by default
with automatic fallback to the original, including the built `nvgpu-fixed.ko` (sha256 `761608e8…f3ec`)
and `install-nvgpu-fix.sh` / `remove-nvgpu-fix.sh`, which work from any clone. `check-same-unit.sh`:
is this unit identical to the one the module was built for (no root). How it works, how to install
on another unit, how to undo: [runbook](../../docs/gpu-driver-fix.md).
